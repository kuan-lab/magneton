## Bug Investigation: `index.json` Race Condition

**Problem:** With `blocks_per_job: 4` and `workers_per_job: 2`, segmentation jobs failed with `json.decoder.JSONDecodeError: Extra data` when calling `save_block_meta()`.

**Root cause:** `save_block_meta()` performed a read-modify-write on the shared `index.json` file (read existing JSON, append new block, write back). When multiple workers in the same SLURM job finished near-simultaneously, two processes would read the file, both append, and both write — the second write corrupted the file with duplicate JSON.

**Why it worked before:** With `blocks_per_job: 1` and `workers_per_job: 1`, only one process ever wrote to `index.json` at a time.

**Fix:** Removed the `index.json` write from `save_block_meta()` entirely. Each worker only writes its own `block_XXXX.json` (unique filename, no contention). `index.json` is built once at merge time by scanning all block files via `build_index()`. `load_index_meta()` caches by checking if `index.json` already exists before rebuilding.
