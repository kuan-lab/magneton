### 1. Modified: `toolkit/tools/downsample_prec.py`

#### Bug Fix: SLURM_MEM_PER_CPU parsed as bytes instead of MB
`SLURM_MEM_PER_CPU` is a plain number in MB (e.g., `32768` for 32G). `parse_memory_string("32768")` matched with an empty unit via the regex `([KMGT]?)`, so the multiplier was `1` (bytes). This meant 32768 was treated as 32768 bytes instead of 32768 MB, displaying as 0.0GB.

The existing fallback on lines 45-47 (`if mem_per_cpu is None`) never triggered because `parse_memory_string` successfully parsed the string — it just returned the wrong value.

**Fix (lines 43-48):** When `SLURM_MEM_PER_CPU` is a plain number (no unit suffix), append `'M'` before passing to `parse_memory_string`:
```python
if re.match(r'^\d+$', mem_per_cpu_str):
    mem_per_cpu_str = mem_per_cpu_str + 'M'
```

#### Bug Fix: Display used decimal GB instead of binary GiB
Print statements divided by `1e9` (10^9, decimal GB) but SLURM allocates in binary GiB (1024^3). This caused 32 GiB to display as 34.4GB.

**Fix (lines 52-54):** Changed `/1e9` to `/GiB` where `GiB = 1024**3`, so printed values match SLURM config (32G displays as 32.0GB).
