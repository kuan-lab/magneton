#### Bug Fix: YAML sexagesimal time conversion
YAML 1.1 interprets unquoted time-like values as sexagesimal (base-60) numbers:
- `10:00:00` → 36000 (int)
- `00:45:00` → "00:45:00" (str) - leading zero prevents conversion

This caused HPC job submissions to fail with `QOSMaxWallDurationPerJobLimit` because `--time=36000` was interpreted as 36000 minutes instead of 10 hours.

**New function `_fix_yaml_time()`:**
- Detects integer `time` values in config dictionaries
- Converts seconds back to HH:MM:SS format (e.g., 36000 → "10:00:00")
- Recursively processes nested dictionaries

**Changes to `edit_stage_config()`:**
- Now loads and fixes config even when user says "n" to modification
- Silently repairs corrupted time values on every run
- Preview (when shown) displays correct HH:MM:SS format

### 2. Fixed: `pytorch_connectomics/configs/hpc_f_bouton.yaml`
